## Most significant gaps
1. **Unbalanced quoting from row reads inside `Text.Trim '…'`** (`pad.py` ~L3925; the same wrapper for `Text.ChangeCase` is at ~L3946). 3 lines:
   - 2 in the PID_0171 Performer: `'dtr_CurrentFinalProduct['Identity']'` and `'dtr_CurrentComponentNames['Value']'`.
   - 1 in the PID_0127 Loader: `'dtr_CurrentParentQ['Sno']'`.

   The base token was balanced, so 8b introduced this. The implementer reported only 2 of the 3.
2. **Declaration-order renders anchor a built loop at the LoopStart's list position**, so a flow predecessor declared after the LoopStart is emitted after the loop.
   - PID_0127 `ConvertConfigFile`: the BP flow is `Append {` → loop → `Remove Last Comma` → `Append }`. The output is now loop → `SET txt_JSONString TO "{"` → …, so the initialiser overwrites everything the loop built. In the base, `Append {` preceded the body lines.
   - The same effect moves `Remove Empty Rows` after the loop in `Populate Queue - Parent`.
   - The implementer did not report this.
3. **4 SPOT-CHECK decision `# VERIFY:` comments disappear** when their decision moves into a loop body, because `_render_chain` never emits them: `Item Already added in Queue?`, `Identity Empty?`, `If Key is not Empty`, `If Exist`. This goes against CLAUDE.md's band table ("inline comment to verify").
4. The `End` no-op fall-through in the new join placement (DownloadCustRequest) makes the success path run the retry IF. This predates 8b and needs the `EXIT FUNCTION` design decision the implementer raised.
5. Deviation 2's report undercounts: the `Mark Item As Exception` `End` move also happens in the PID_0127 Performer.
