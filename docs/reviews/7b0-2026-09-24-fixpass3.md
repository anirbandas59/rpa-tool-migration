## Most significant gaps

1. **Phantom cross-role inits in the Performer Main.** `_collect_hoistable_stage_sources` (`pad.py`
   L1190-1210) recurses into subsheet calls whose target role differs from the current role.
   `_render_stage_in_main_page` (L627-629) skips those calls, so 21 Loader-only inits (Populate
   Queue, ConvertConfigFile, Read Excel) appear at P139-146 and P173-185 for content that is never
   rendered. Fix: apply the same `target_page.role != role` filter in the Main-per-role collection.
2. **The flow `@INPUT` `flg_SendDatatoDataGateways` is overwritten** by the hoisted `SET ... TO False` (P207)
   at the top of the Performer Main. Main hoisting passes `set()` as the bound-name set (L569), but
   Main's Start inputs are parameter-bound, since they become `@INPUT`s. Item 8 applies to
   "(non-parameter-bound) data items". Fix: exclude the Main page's Start-stage input items, as Do
   item 3 does for FUNCTIONs.
3. **Design decision needed: the per-run reset semantics of inline_block/fold content.** Item 8
   says an inlined page's inits go to the host's top. The rationale behind item 8 ("initial values
   apply when the page starts") means an inlined page should reset on each inlined execution. In
   PID_171 this:
   - empties the `Reset Global Data` fold (P229-234; mapping note "Variable-reset per-item"), so
     `flg_IsCompleted`, `txt_ExceptionType`, `dt_*` and the rest no longer reset between queue items;
   - stops the second `Sample Manager - Explorer` inline in `Enter Results in App` from resetting
     `num_RetryCount` (fp2 L1090 is removed with no replacement).

   Candidate rule: keep an inlined page's inits at the start of its inlined block (its own "page
   start"), and hoist only names that collide with a host item, which covers the Loader
   `dtb_MailItems` case. Alternatively, accept once-per-host with a `# TODO` at each inline site
   that resets per run. **Coordinator ruling needed.** This is not an implementer defect.
4. **Item 9 covers only re-inits, not references.** 13 BP stages across all 5 non-entry Result Entry
   sub-FUNCTIONs read `FinalProduct_Collection`, `SampleID` or `ProductException` (listed above),
   and none gets a TODO (`pad.py` L1674 only inspects DATA/COLLECTION targets). Item 9 says
   "reference or re-initialise". Those stages currently render as placeholder comments, which
   hides the problem in output but does not satisfy the item.
5. **Item 11 is not met for 3 behaviours.** Each of these mutants leaves every test passing:
   - M3: the item-9 test regex `^SET txt_WidgetSourcePath TO` (`test_pad.py` L3571) is vacuous,
     because the split path renders the raw `widget_source_path`. Assert that no line matches
     `^SET \S*[Ww]idget_?[Ss]ource_?[Pp]ath TO`, or pass a mapping.
   - M5: there is no test for transitive inline_block/fold hoisting, the Loader `dtb_MailItems` fix.
   - M6: there is no test for Main-per-role hoisting, the Performer P286/P292 fixes.

   Also add tests for gaps 1 and 2 (role filter, `@INPUT` exclusion).
6. **The item-10 assignment regex has its direction inverted** (`pad.py` L1316). `\bOut_x\s*=>`
   matches the *callee's* parameter in `CALL ... Out_x=> var`, not a write to `Out_x`. It should be
   `=>\s*Out_x\b`, covering both action outputs and CALL captures into `Out_x`. It is latent in
   PID_171, but it will produce false TODOs as soon as VBO/Excel actions write outputs.
7. **Minor.** Identical hoisted inits are not deduplicated (P143/P162, P173/P183, Loader L117/L127).
   The claimed "one-level" limit is inaccurate: the recursion is unbounded with a cycle guard,
   which is fine. The implementer's summary should be corrected.
