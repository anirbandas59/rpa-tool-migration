## Root cause of the well-formedness gap (new finding, not raised by implementer or prior review)

`ast/builder.py`'s `_SKIP_TYPES` correctly drops `Anchor` stages per CLAUDE.md's skip-type table
("Skip types (no AST node, no generated output): ANCHOR, NOTE, SUBSHEETINFO, PROCESSINFO"). But
Anchor stages are purely visual bend-points in BP's execution graph — a stage's `onsuccess_target`
routinely points *at* an Anchor, whose own `onsuccess_target` then points at the real next stage.
Dropping the Anchor's `BPStage` without also collapsing/redirecting the edge that pointed to it
means any chain routed through an Anchor is truncated: the BFS pops the Anchor's ID, finds it's not
in `stage_to_page` (because no `BPStage` was ever created for it), and silently stops there —
losing the rest of that execution branch, including every page reachable only via it.

Verified directly against the real sample:
- Traced by hand: `Mark Item As Completed`'s own `onsuccess_target`
  (`d60b360f-7627-427e-9f30-4ae70e44b7a1`) resolves in the *raw* (pre-normalisation) parser output
  to `stage_type: "Anchor"`, name `Anchor14`, whose own `onsuccess_target`
  (`3c860475-9175-4e7a-8af0-3d3981dad5a5`, the `DataGateway` ACTION stage) is never followed by the
  BFS, because the Anchor's `BPStage` doesn't exist in `stage_to_page`.
- Quantified the scale: of 456 total `onsuccess`/`ontrue`/`onfalse` edges in the main process, 58
  (~13%) point directly at an `Anchor` stage (43 Anchor stages total in the process) — this is not
  a one-off, it's systemic.
- Confirmed the downstream effect by BFS-tracing the main page by hand: only 22 of its 108 stages
  are ever visited, and only 10 of 24 pages total are marked reachable, even though several of the
  "unreachable" pages have real, verifiable callers already present in the AST — e.g. `Send mail`
  is called twice from Main Page (`d0547b46-…`, `a67912e4-…`, both real `is_subsheet_call` stages
  with a matching page name), `Reset Global Data` is called once (`bef8f1ff-…`), `DataGateway` is
  called once (`3c860475-…`), and `Sample Manager - Explorer` is called three times from the
  (reachable) `Result Entry` page — all of these caller stages themselves are simply never reached
  by the BFS because the chain leading to them passes through a dropped Anchor first.
- Cross-checked against the architecture doc's own independently-derived ground truth (§B14's
  page table, cross-validated against `bp_report_v2.py`'s "Called by" column and a `<processid>`
  search, and explicitly re-verified in the doc's own "Review Notes" section) — confirms all of the
  above pages are real, called, non-orphan pages. Only `Mark leftout Items as Exception` and `Send
  Info to Data Gateways` are genuine orphans.

This is not a scope-creep finding from a different task — it lives entirely inside `ast/builder.py`
(`_normalise_stages`'s skip-type handling and `_compute_reachability`'s BFS), squarely inside this
task's own declared file scope, and it directly undermines the deliverable's core purpose
(distinguishing genuine orphan pages from called ones across the whole process, not just the two
named examples the task's own Do-step 4 happens to spot-check).

## Verification of the specific items raised for this re-review

**1. Page-count reconciliation (23→24 / 18→19).** Confirmed correct, not a spurious duplicate.
Read `git diff src/flowsmith/parser/process.py` directly: the old code merged `main_stages`
(stages with no `<subsheetid>`) into whichever subsheet was picked as the (buggy) "main" page —
conflating two logically distinct things into one page and silently deflating the true page count
by exactly one. The fix creates a **new**, separate page for the implicit main-flow stages (per
CLAUDE.md rule 2, which describes the implicit Main Page as distinct from every named subsheet),
and leaves the previously-mis-picked subsheet as its own separate page. Verified with a direct

## Most significant gaps

- **New, unaddressed defect (this file's own scope): dropping `Anchor` stages without collapsing
  their pass-through `onsuccess` edge breaks the reachability BFS at ~13% of all edges in the real
  sample**, causing 12 of the 24 real pages to be wrongly marked unreachable despite the
  architecture doc's own ground-truth confirming they have real callers. This is a more consequential
  problem than either of the two bugs this fix pass actually targeted, and it was not surfaced by
  the implementer (whose own reported numbers — "14 unreachable, 10 reachable" — were taken as the
  correct outcome rather than checked against the architecture doc's orphan list).
- **The Block→Recover pairing is not persisted anywhere reusable** — it's computed and discarded
  inside `_compute_reachability`'s BFS, so a later rendering task (per Do-step 2's own stated
  rationale) gets no benefit from this pass's work and will have to redo the "nearest enclosing
  Block" resolution from scratch, ideally with real nesting-depth tracking rather than a
  document-order heuristic that a constructed counterexample shows can mispair.
- **`engine/annotator.py` was not updated to recognise `is_process_call`**, so the one real
  `Process`-type stage in the sample is now preserved (correct, per this task) but mis-annotated as
  a parser-error/`MANUAL`/error-flag case instead of using Task 2c's already-written
  `stage_rules.yaml` `Process` row (`confidence_base: 0.5`, `pa_module: "External"`). Out of this
  task's declared scope, but should be flagged as urgent unfinished coupling, not silently
  discovered later.
- **5 of 8 newly-broken full-suite tests were not disclosed** in the implementer's summary
  (`tests/engine/test_scorer.py` ×4, `tests/engine/test_annotator.py` ×1) — all turned out to be the
  same benign stale-count pattern as the 3 that were disclosed, but the implementer should have run
  `uv run pytest tests/ -q` (not just the narrowly-scoped file list) before declaring "0 failed."

## Verdict

**Needs another implementation pass.** Real, verified progress was made on the two specific bugs
and on process discipline (honest deviation disclosure, a genuinely-restored non-tautological
acceptance test). But the task's actual deliverable — a call-graph model that correctly
distinguishes orphan pages from called ones across the whole process, not just the two named
examples in its own Do-step 4 — is still wrong for roughly half of the real sample's pages, due to
a newly-identified defect (`Anchor` pass-through-edge collapse) that lives squarely inside this
task's own file scope and was not caught by the implementer's own checks. Recommend: (1) fix
`_normalise_stages`/`_compute_reachability` to redirect any edge pointing at a dropped `Anchor`
stage to that Anchor's own downstream target (recursively, for Anchor chains) before running the
BFS, (2) re-run reachability against the real sample and confirm it now matches architecture doc
§B14/§B16's ground truth (22 reachable / 2 orphan, not 10/14), (3) escalate the
`engine/annotator.py` `is_process_call` gap to the coordinator as urgent follow-up work (Task 2c's
`stage_rules.yaml` `Process` row is currently unreachable dead data), and (4) run the full suite
(not just the task's own scoped files) before the next "done" declaration.
