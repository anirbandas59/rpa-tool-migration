This is a second review of Task 1 on the same day. The prior report
(`docs/reviews/1-2026-08-28.md`, scored 55%, verdict "needs another implementation pass") found a
verified regression: the router degraded confidence to an invented `0.3` for known VBOs whenever

## Findings

1. **Regression confirmed fixed.** The specific bug identified in the prior review — degraded
   confidence in the `method_actions`-empty branch — is gone. Verified two ways: direct code
   reading of `vbo_router.py` lines 144-148, and the full `tests/engine/test_scorer.py` suite
   passing (previously 3 failures, now 0).
2. **New, undisclosed defect: invalid UTF-8 byte in `vbo_router.py` breaks `ruff`.** Introduced by
   this task's own edit (confirmed via `git diff`), not pre-existing. `ruff check` cannot process
   the file at all (`E902`). CLAUDE.md requires a clean `ruff check` before commit; this file
   currently cannot even be linted. Not mentioned in the implementer's summary.
3. **Task step 4's "lower confidence for fuzzy fallback" is not implemented — and this is
   under-disclosed as a full non-issue.** The summary characterizes the deviation accurately in
   spirit ("kept the fallback logic... without any confidence degradation") but doesn't mention
   that this leaves genuinely dead code in the router (`method_matched` computed, never read —
   confirmed via `ruff F841` on a decode-fixed copy) or that two of the 8 new
   `TestMethodActionsPrecedence` tests have docstrings that assert the opposite of what the test
   body actually checks:
   - `test_exact_match_has_higher_confidence_than_fuzzy` — docstring: *"Exact method_actions match
     has higher confidence than fuzzy pattern match."* Actual assertion:
     `exact_decision.confidence == fuzzy_decision.confidence` (i.e. **equal**, not higher).
   - `test_fuzzy_pattern_match_reduces_confidence` — docstring: *"Fuzzy method_patterns match
     reduces confidence by 20% when method_actions is present."* Actual assertion:
     `decision.confidence == 1.0` (i.e. **not reduced at all**).
   Both tests pass, so the suite is green, but the docstrings describe behavior the code doesn't
   have — this is the same category of "misleadingly named test gives false sense of coverage"
   finding the prior review flagged (there, a test named `test_no_method_actions_behaves_as_before`
   didn't exercise the actual regression case). It recurred here in a new form despite being
   called out last time.
   Practically: since `method_actions` is empty for every real catalogue entry today, this is
   dormant, but it means when Task 2b populates `method_actions`, an entry with some methods
   templated and others only pattern-matched will get **identical** confidence for both — the
   task's own literal requirement ("an exact `method_actions` match takes precedence over and
   yields higher confidence than a `method_patterns` fuzzy match") will not hold, and nothing in
   the current test suite would catch that because the two tests that claim to check it don't.
4. **`config.py` schema addition is untouched and correct** (confirmed identical to the prior
   review's assessment — `method_actions: dict[str, str] = Field(default_factory=dict)`, correctly
   optional/defaulted, correctly typed).
5. **File-scope discipline mostly holds** — `mapping/vbo_catalogue.yaml` untouched (correctly
   deferred to Task 2b) — but the working tree also carries an unrelated, out-of-scope
   `.claude/skills/pad-review/SKILL.md` change not mentioned in the implementer's summary and not
   part of Task 1's declared file scope. Minor; flagged for hygiene, not scored against this task.

## Most significant gaps

1. **`src/flowsmith/mapper/vbo_router.py` contains an invalid UTF-8 byte introduced by this fix
   pass**, breaking `ruff check` entirely (`E902`). Trivial to fix (re-save the comment with a
   proper UTF-8 em-dash or plain ASCII `--`) but must be fixed before commit per CLAUDE.md, and was
   not caught by the implementer (their summary doesn't mention running `ruff` at all).
2. **Task step 4's confidence-differentiation requirement is not met**, and the two tests meant to
   cover it (`test_exact_match_has_higher_confidence_than_fuzzy`,
   `test_fuzzy_pattern_match_reduces_confidence`) have docstrings that describe the opposite of
   what they assert. This is dormant today (no real `method_actions` data exists yet) but will
   need to be resolved — either by implementing an actual (cited, non-invented) confidence
   differentiation before Task 2b lands real data, or by an explicit design decision to treat
   exact/fuzzy matches identically, with the docstrings and dead `method_matched` variable cleaned
   up to match whichever choice is made.
3. **The core regression from the prior review is genuinely fixed and independently
   reverified** — this is the main positive finding of this follow-up, not a gap, but worth
   stating plainly since it's the reason the score moved from 55% to 80%.

## Verdict

pass, with two follow-up items to close before this is fully clean: (a) fix the invalid-UTF-8 byte
in `vbo_router.py` so `ruff check` can run at all, and (b) either implement the task's literal
"fuzzy match gets lower confidence than exact match" requirement with a cited value, or get
explicit sign-off to drop it and clean up the two misleading test docstrings plus the dead
`method_matched` variable accordingly. Neither blocks Task 2a/2b (which don't depend on this
specific behavior), but both should be closed before Task 2b starts populating real
`method_actions` data, since (b) directly affects how that data will be scored for confidence.
