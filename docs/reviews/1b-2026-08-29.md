## Most significant gaps

- **The task's central "Done when" criterion (a) is not met, and the implementer's summary does not disclose this.** The summary lists "Excel Create+Open pair resolves correctly" / "Excel Close+Close pair resolves correctly" as test results without noting these are synthetic fixtures, not the real `PID_0171.bprelease` page named explicitly in the task prompt. Running the real pipeline against the real page (which I did, using a synthetic router since `vbo_catalogue.yaml` has no `fusion_patterns` data yet — correctly out of scope per Task 2b) shows **zero** fusion candidates detected and **zero** `ReviewFlag`s created for either of the two required pairs — a silent miss on both.
- **Root cause is a parser/AST-contract gap, not just a missing test.** `src/flowsmith/parser/process.py` never parses `<outputs>` elements on any stage type, and routes ACTION `<inputs>` into `params_map` rather than `data_items`. `_detect_vbo_call_fusions` structurally cannot see the numeric-handle handoff without this data reaching `BPStage.data_items`. Fixing this requires touching `parser/process.py`, which is outside Task 1b's declared file scope (`ast/builder.py`, `ast/models.py`, `tests/ast/test_builder.py`) — this should have been surfaced as a blocking cross-task dependency/finding in the implementer's summary, not silently worked around with fixtures that assume a data shape the real parser never produces.
- **Adjacency check is list-position-based, not `onsuccess`-edge-based.** The task's step 1 requires "stage N's sole `onsuccess` target is stage N+1, no branching in between" — but neither `RawStage` nor `BPStage` carries `onsuccess` edge data anywhere in the codebase (confirmed via grep), so the implementation approximates adjacency using raw stage-list order. This happens to work for the two known Excel pairs (which are XML-document-adjacent) but is not a faithful implementation of the spec and could misfire on pages where document order and execution order diverge.
- Coverage of the new function itself is incomplete for the "unmatched VBO / mismatched VBO" branches (lines 447, 458, 475, 490, 507-508 uncovered per the `tests/ast/` coverage report) — minor relative to the above.

## Verdict
blocked pending a design decision — Task 1b's detection logic is well-structured and correctly reuses the existing bracket-pairing pattern, and its resolution/flagging logic is correct when fed data in the shape the task assumed. But it cannot satisfy its own "Done when" criterion without `parser/process.py` gaining `<output>` parsing for ACTION stages (and likely moving ACTION `<input>` elements into `data_items` too) — a change outside Task 1b's declared file scope. This needs either a scope amendment to Task 1b or a new prerequisite parser task, followed by another implementation pass to re-verify detection against the real `Read Excel As Collection` page (not synthetic fixtures) before this can be marked done.
