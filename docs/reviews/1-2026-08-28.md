## Most significant gaps

1. **Verified regression that violates the task's own explicit "no regression" requirement.**
   Before this change, a *known* VBO always returned `confidence = entry.confidence_base`
   regardless of whether the method name matched anything in `method_patterns` (confirmed by
   reading `git show HEAD:src/flowsmith/mapper/vbo_router.py`, lines ~112-131 — no method-level
   matching existed at all). The implementer's new code, in the `method_actions`-empty branch
   (the branch every current `vbo_catalogue.yaml` entry takes today, since Task 2b hasn't run),
   *added* a method_patterns match requirement: if the method name doesn't match, confidence now
   drops to `0.3` instead of staying at `entry.confidence_base`. Reproduced directly:
   ```
   git stash  (pre-Task-1 code)
   router.route('MS Excel VBO', 'Some Totally Unlisted Method') → confidence: 0.8
   git stash pop  (post-Task-1 code)
   router.route('MS Excel VBO', 'Some Totally Unlisted Method') → confidence: 0.3
   ```
   This directly contradicts task step 5's requirement: *"a `VBOEntry` with no `method_actions` at
   all behaves exactly as before — no regression."* The implementer's own regression test,
   `test_no_method_actions_behaves_as_before` (`tests/mapper/test_vbo_router.py:494-511`), is
   misleadingly named — it only exercises the case where the method name *does* match a pattern
   (`"Classic Pattern"`), never the mismatch case where the regression actually lives, so it gave a
   false sense of "no regression" coverage.
2. **This regression is not confined to `tests/mapper/` — it breaks the wider suite.** Running the
   full suite (`uv run pytest tests/ -q`) after this change: **3 failures** in
   `tests/engine/test_scorer.py::TestRealSampleScoring` (`test_real_sample_spot_check_count_4808`,
   `test_real_sample_partial_count_154`, `test_real_sample_manual_count_489`) that all pass cleanly
   on the pre-Task-1 code (`git stash` + rerun confirms `46 passed` before, `3 failed` after). These
   tests assert fixed confidence-band counts (AUTO/SPOT-CHECK/PARTIAL/MANUAL, per CLAUDE.md's
   confidence-band table) across the real `PID_0171.bprelease` sample — the new degraded-confidence
   fallback shifts real stages between bands. The implementer's "Done when" check
   (`uv run pytest tests/mapper/ -v`) never surfaces this because it only runs the narrowly-scoped
   test file, but the defect is real and will need fixing before Task 2b/5b build on top of this
   router.
3. **Implementer's summary overstates completeness.** "Deviations from task spec: None." and "Open
   questions: None. All requirements met and all tests passing" are not accurate given finding 1-2
   above — the "no regression" requirement (explicitly called out in the task's own step 5) is not
   met, and this wasn't caught or disclosed.
4. **The task's literal "Done when" command exits non-zero.** `uv run pytest tests/mapper/ -v`
   reports `165 passed` but the process exit code is `1`, because `pyproject.toml`'s
   `[tool.coverage] fail_under = 85` gate applies globally and a mapper-only subset run only
   exercises ~39% of `src/flowsmith`. Verified this is **pre-existing** (reproduced the same exit-1
   behavior by `git stash`-ing this task's changes and re-running against the base commit — 155
   passed, same coverage-gate failure) — not something this task introduced, but the implementer's
   summary reporting "**165 passed** in 5.23s" as unqualified success glosses over the fact the
   command itself doesn't exit clean. Worth flagging upstream (pytest config), not chargeable to
   this implementer beyond the reporting-accuracy point.
5. **Minor: 2 ruff lint violations** (`SIM108`, both in `vbo_router.py`'s new `if`/`else` blocks
   that ruff wants collapsed to ternaries) — `uv run ruff check src/flowsmith/mapper/config.py
