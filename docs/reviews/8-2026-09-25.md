### Verification of the implementer's claims

- **Correct:** the band counts, the flag totals, "all 749 annotated", "0 `pending_flags` in PID_0171", "32 unflagged (19 PARTIAL + 13 MANUAL)", the zip rejection, "ruff clean", and "954 passed / 10 known failures".
- **Needs a correction:** the open question "13 MANUAL stages carry no error flag" understates the gap. **16** MANUAL stages have no `error`-severity flag: 13 have no flag at all, and 3 (the env-lock Acquire/Release Lock stages) have only a `warn` flag. Both cases contradict the CLAUDE.md MANUAL row, "Stub only + ReviewFlag(severity=error)".
- **Additional engine finding the implementer missed:** the 14 LOOP errors say "No mapping rule for stage type 'LOOP'", yet `mapping/stage_rules.yaml` has `canonical_type: LOOP` rows (L157, L172). So 14 of the 19 error flags (74%) are probably an annotator lookup false positive, not real developer work. The reporter shows them faithfully, but they add noise to the checklist.

### Declared deviations — assessment

1. **The "PARTIAL / MANUAL stages with no ReviewFlag" section is justified. Keep it.** Its text invents no reason ("No ReviewFlag reason or suggested fix was recorded by the engine"). It is the only place 11 SampleResultsEntry UI actions and 1 SampleManager UI action appear as work items, and those are the UI-selector build items the report exists to surface. Once the engine is fixed, the section should become an empty-when-healthy safety net.
2. **Surfacing `pending_flags`** is harmless (0 here) and stops Task 1b flags from being lost silently. Accept it.
3. **`--format terminal` writing no file** is reasonable. Accept it.

## Most significant gaps

1. **Engine follow-up needed (outside this task's scope, and this review recommends a named task for it).** CLAUDE.md's band contract is not met by the engine:
   - (a) 16 MANUAL stages lack an error flag (13 with none, 3 with warn only), in the `annotator._annotate_action` VBO path.
   - (b) LOOP stages get a false "No mapping rule" error even though `stage_rules.yaml` has LOOP rows. This accounts for 14 of the 19 errors.
   - (c) `pending_flags` are never transferred onto `pa_annotation.flags`.
   - (d) `vbo_router.py:158` truncates the reason at 120 characters.
   - (e) Stale real-sample totals in the 8 `test_flag_index` tests and the 2 `test_vbo_router` tests.

   Until (a) and (b) are fixed, the report's checklist is both noisy (14 false LOOP errors) and incomplete (the real UI-selector work sits in the unflagged section instead of the flag list).
2. **LOOP flag entries are thin.** The reporter could show `pair_id`/`group_id`, or a start/end marker, so the duplicate "Final Product" entries can be told apart. The iterated collection is not in the AST (a parser gap).
3. **External process calls show only a GUID**, not the called BP process name.
4. **The Done-when command exits 1** because of the global `fail_under` on a subset run. This needs either a doc/config decision or to be accepted as known (for example, run it with `--no-cov`).
5. **Minor:**
   - There is no `tests/reporter/test_models.py`.
   - The template directory depends on the cwd, so the report fails outside the repo root. It shares this with the packager, and it matters for the ~200-developer rollout.
   - The terminal prints `SPOT_CHECK` where the HTML and CLAUDE.md say `SPOT-CHECK`.
