## Answers to the coordinator's specific checks

- **(c) The "VBO stub" explanation is only partly true.** It is true for Fetch Emails: every bound item is referenced only by the `Get Mails` VBO action, which renders as a comment stub, `# External.Get Received Items ...` (L382). For Send Email, the `Send Mail` VBO stub accounts for 5 of the 6 inputs. `ItemData_Subject`, however, is read by the CALCULATION stages `System Exception` and `Bussiness Exceptions`, and those render as the generic placeholder `# Variables.SET <var> TO <expr>` (P708, P713). The annotator gives them the target type `SET <var> TO <expr>`, not `SetVariable`, so they fall through `_render_stage`. That is a pre-existing Task 5b/annotator gap, not a VBO gap. The same fall-through hides the `Out_txt_SampleID` writer (`Get Sample ID`, P695) and the `Result Entry`/`Summary_Report` calculations. Excel actions render with hardcoded placeholder arguments (`pad.py` L2287-2295: `Path: $'''C:\path\to\file.xlsx'''`, `RangeValue=> DataTable`), so `In_txt_ExcelFilePath`, `In_txt_SummaryFilePath` and similar are never consumed. Those are placeholders, not stubs. **In every case, no body references a bound item under its old name.** The absence of `In_` reads is caused by the untranslated stages, not by missed overrides, and the mutation run confirms the overrides would apply.
- **(d) Unassigned `Out_` in a non-split FUNCTION.** The section requires a TODO only for the split case (Do item 3, "It must not be left silently unassigned"). It does not require one for non-split pages. For `Send Email`'s `Out_txt_ItemsCompleted` the absence is faithful to BP: `Items Completed` in `Send mail` has an empty `<initialvalue />` and no stage in the page writes it, so BP returns "". For the other 3 unassigned outputs, the writing stage *is* present as a stub or placeholder comment, but that comment does not mention the `Out_` binding it should feed. The house rule "never silently drop" argues for a one-line marker, `# TODO: Out_x is not assigned in this body`, whenever no body line assigns a declared `Out_`. This is recommended, not required by the section's letter (gap 4).
- **(e) `_current_suppress_init_names` is reset reliably.** Both entry points save the previous value, set the new one, and restore it in `finally` (`pad.py` L1180-1202, L1381-1405). It is therefore exception-safe and nest-safe. The legacy `generate_page` path never sets it, so the default empty set applies. **Latent leak:** `inline_block`/`fold` targets rendered from inside a parameterised FUNCTION body (`pad.py` L754-759, L788-792) inherit both the host's override map and its suppress set. A folded page's own data item with the same name as a host parameter would be silently renamed or suppressed. PID_171 does not trigger this, because the only folds sit inside bare split sub-FUNCTIONs (P847, P1024, P1070). This is minor.
- **(f) The citations support the pattern only partly.** L944 is `SET out_dtb_filteredTable TO In_dtb_FinalProduct` in `Enter Results in App` (header L768), placed before `EXIT FUNCTION`. It supports the `SET Out_ TO In_`-before-exit form, though with different item names, not the same item bound both ways. L395-396 (`SET out_dtb_DataCollection TO dtb_ExcelData`, `SET out_txt_SampleId TO txt_SampleId`) show copy-a-local-to-`out_` at the end. They do **not** show `SET Out_x TO In_x`. They also contradict the docstring claim at `pad.py` L1080-1082 that they "confirm bodies read/write the parameter name directly": those bodies use locals. The behaviour itself follows the section's binding decision. The problem is citation accuracy only (gap 5).
- **(g) No hardcoded PID_171 names in `src/`.** The only PID_171 names in the added `src/` lines appear inside reference-citation comments (L232/L944/L395 quotes).

## Most significant gaps

1. **The core "no input re-initialisation" behaviour is untested.** The test's assertion
   `"SET txt_WidgetSourcePath TO" not in rendered` (`tests/generator/test_pad.py` L3179) cannot fail
   once the override is merged, because an unsuppressed init renders as
   `SET In_txt_WidgetSourcePath TO ...`. Disabling suppression at `pad.py` L2183 leaves all 824
   tests green and regenerates the exact prior gap-1 defect (Loader `SET In_txt_Subject TO %SomeVar%`
   and so on). Do item 7 explicitly requires this check. The fix: assert that no line matches
   `^SET (In_)?txt_WidgetSourcePath TO`. Also add two tests: output-only `Out_` naming in the body,
   and COLLECTION (`DataTable.Create()`) suppression.
2. **The clobber report (Do item 6) misses the clearest caller-side clobbers.** In the Performer main
   body, a collection returned by a CALL is wiped by the caller's own declaration `SET` before it is
   used:
   - P143 `Out_dtb_FinalProductCollection=> dtb_FinalProductCollection` → P286
     `SET dtb_FinalProductCollection TO DataTable.Create()` → P291, which passes it as
     `In_dtb_FinalProductCollection`.
   - P291 `Out_dtb_FinalProductCollection=> dtb_SammaryCollection` → **P292**
     `SET dtb_SammaryCollection TO DataTable.Create()` → P293, which passes it to
     `Create Summary Report`.
   - Loader L109 `Out_dtb_Items=> dtb_MailItems` → L154 `SET dtb_MailItems TO DataTable.Create()`.

   The two items the report does list (`txt_ItemsCompleted` P277/P278/P355 and `txt_SampleID`
   P143/P394) are correct. The collection cases above are the higher-impact ones, and the section
   named `dtb_FinalProductCollection` as an example. This task only has to report them, not fix them.
3. **Split sub-FUNCTIONs silently lose `Result Entry`'s inputs.** P842, P843, P895 and P944 re-init
   `txt_ConfigAnalysisWorkSheetName`, `txt_ConfigParameterWorkSheetName`, `txt_ProductException` and
   `num_DownArrowSec` to `%SomeVar%` in bare sub-FUNCTIONs. The caller's values arrive only as the
   entry's `In_` params, which are out of scope there. The section's split rule handles only the
   `Out_` side. By the same "must not be left silently" logic, the entry (or each sub-FUNCTION)
   needs a `# TODO` naming the `In_` params that the missing split call chain does not propagate.
   **Coordinator decision needed:** the section does not state this rule.
4. **Unassigned `Out_` params in non-split FUNCTIONs have no marker.** There are 5 instances (L337,
   P586 ×2, P705, P1253). Adding a marker is recommended rather than required; see (d). The cheap
   option: after rendering a body, emit `# TODO: Out_x is declared but not assigned in this body`
   for each declared `Out_` whose name never appears on the left-hand side of a `SET`/`=>`.
5. **Citation accuracy.** The `pad.py` `_build_body_variable_overrides` docstring and the comment
   at ~L1173 cite L395-396 as showing bodies that "read/write the parameter name directly". They
   show the opposite: locals copied to `out_` at the end. Keep L944 and reword the L395-396 claim.
6. **Latent override/suppress leak into `inline_block`/`fold` content** rendered inside a
   parameterised FUNCTION (`pad.py` L754-759, L788-792). PID_171 does not trigger it. Clear the
   suppress set and use the un-overridden mapping when rendering a folded or inlined target
   page's stages.
7. **Outside 7b0's scope, but it limits verification.** CALCULATION stages annotated
   `SET <var> TO <expr>` fall through to a placeholder comment: 92 in Performer and 13 in Loader.
   Excel actions use hardcoded arguments (`pad.py` L2287-2295). Until the Task 5b translator and
   the VBO work land, no real-output body can demonstrate an `In_` read or an `Out_` write. Only the
   synthetic tests do. Route this to 5b/7a follow-ups, not to 7b0.
