### Coordinator's question: is the LOOP SPOT-CHECK/VERIFY output a regression in honesty?

**Yes, for those 14 stages the generated `.robin` is now less honest, even though the engine score
is now correct.**

**What the output looks like** (Performer ~L535):
- The LoopStart and LoopEnd lines are rendered **adjacent to each other**, both as
  `# System.LOOP FOREACH <item> IN <collection> ... END | LOOP <var> FROM ... # VERIFY: Loop Input (confidence 0.80)`.
- The loop body follows as plain linear statements, which would run once, not iterate.
- The output contains no loop at all, only a commented template with `<placeholder>` tokens.

**Why this is misleading:** CLAUDE.md's band table defines SPOT-CHECK as "Full code + inline comment
to verify". A `# VERIFY:` marker here tells the developer "working code, just check it", when in
fact nothing is built. The old stub was also wrong: it said "Add rule to mapping/stage_rules.yaml",
but the rule exists. It did at least say "implement manually", which was the right action.

**Cause: this task exposed the problem, it did not create it.**
- The generator has no LOOP renderer. Its generic fallback already emits
  `# <module>.<template> # VERIFY:` for any SPOT-CHECK stage it cannot render. The same pattern
  existed before this task, for example `# Variables.Remove Row # VERIFY: Remove Row (confidence 0.70)`.
- `stage_rules.yaml` rates `LoopStart` at 0.80 (Task 2c) without any renderer behind that rating.
- Task 8a was required to let item 1's corrected lookup set the score ("changing confidence scores
  beyond what item 1's corrected rule lookup produces" is out of scope). The generator is outside
  its file scope, so it had no legal way to fix this.

**What should happen** (a new generator task, not a re-pass of 8a):
1. **Honesty rule (small, do first):** whenever the generator falls back to a commented-out template
   that still contains `<...>` placeholder tokens, it should emit a `# TODO:` stub naming the stage
   and construct, whatever the band. This also fixes the existing `Remove Row`-style cases.
2. **Real LOOP rendering:** pair LoopStart/LoopEnd by `group_id` and emit
   `LOOP FOREACH <item> IN <collection>` around the body. This depends on the parser recording the
   loop's collection, which Task 8a already lists as an out-of-scope gap.
3. Lowering `LoopStart`'s `confidence_base` until then is an alternative, but it would misstate
   mapping confidence to paper over a generator gap. I recommend 1 + 2. That is a design decision for
   the coordinator.
