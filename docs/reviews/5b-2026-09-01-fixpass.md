# Review: Task 5b — 2026-09-01 (fix-pass verification)

This review verifies a targeted fix pass against the single blocking gap identified in
`docs/reviews/5b-2026-09-01-rereview.md` (62%, "needs another implementation pass"): the
Done-when criterion — "a new test asserts that generating a `Calculation` stage with a known BP
expression ... produces the exact expected `SET txt_ExceptionType TO ...` line, not a
placeholder" — was unmet, and the closest existing test had a logically defective disjunctive
assertion that could never fail. This is not a from-scratch review; it verifies whether the
fix pass closes exactly that gap without regressing anything else, per the standard §4
methodology.

## What changed

`git diff` confirms the implementer's claim precisely: **only** `tests/generator/test_pad.py`
was touched (no `src/flowsmith/generator/pad.py` or template changes). Three changes, all as
claimed:

1. `make_annotated_stage` helper gained a `stage_params_map` parameter and now sets
   `stage.params_map = stage_params_map or {}` on the constructed `BPStage` (previously the
   helper only ever populated `PAAnnotation.params_map`, never `BPStage.params_map`).
2. `test_calculation_stage_uses_variable_name_mapping_for_target`'s assertion was rewritten from
   `assert ("dtb_..." in result or "FinalProduct_Collection.Column8" not in result)` to a strict
   `assert "dtb_FinalProductCollection.Column8" in result`, and its stage construction switched
   from `params_map=` to `stage_params_map=` (plus an added `output_value` → `txt_OutputValue`
   mapping entry).
3. New test `test_calculation_stage_renders_real_expression_not_placeholder`: builds a
   CALCULATION stage with `stage_params_map={"Exception Type": "[Exception Type]"}`, renders via
   `gen._render_stage(calc_stage, process, {}, mapping)` with
   `mapping={"exception type": "txt_ExceptionType"}`, and asserts both
   `"SET txt_ExceptionType TO txt_ExceptionType" in result` and `"%SomeVar%" not in result`.

## Independent verification (not just trusting the summary)

**1. Traced the `pad.py` source claim directly.** At `src/flowsmith/generator/pad.py` lines
~1595–1603, the `SetVariable`/`CALCULATION` branch reads `target_var_name`/`bp_expr` from
`stage.params_map` (`next(iter(stage.params_map.keys()/.values()), ...)`), not from
`annotation.params_map`. `BPStage.params_map` and `PAAnnotation.params_map` are confirmed as two
distinct Pydantic fields (`src/flowsmith/ast/models.py` lines 124 and 248). This confirms the
implementer's claim: the pre-fix `make_annotated_stage` helper was structurally incapable of
constructing a valid CALCULATION-stage fixture, because it never wrote to `stage.params_map` at
all — any test built with it for a CALCULATION stage was exercising the "no params_map, fall
back to stage name + `%SomeVar%`" branch regardless of what the caller intended.

**2. Read both fixed/new tests directly** — both assertions are genuinely strict positive
(and, for the new test, an added strict negative) checks, not superficial rewrites. They would
fail if the code regressed to the placeholder or the old vacuous disjunction reappeared.

**3. Ran the full test file:** `uv run pytest tests/generator/test_pad.py -v --no-cov` →

(`test_calculation_stage_uses_variable_name_mapping_for_target`,
`test_calculation_stage_renders_real_expression_not_placeholder`) pass individually within that
run.
