## Coordinator checklist

1. **Typed exception claim: verified.** The `except Exception: pass` is gone. A copy of `mapping/`
   with `queue_bindings: ["just a string", …]` makes `load_rules()` raise
   `ConfigError: Invalid YAML content: 1 validation error for VBOEntry queue_bindings.0 …`. That works
   because Pydantic's `ValidationError` is a `ValueError`, which `config.py` L275-276 catches.
   `PADGenerator()` wraps it as `GenerationError: Failed to load mapping config: …` (`pad.py`
   L127-130). Nothing is swallowed on the new init path (`pad.py` L132-145). One soft spot remains:
   if the `clsWorkQueuesActions` entry is missing entirely, `get_vbo_entry` returns `None` and
   `queue_bindings` silently stays `{}`. That is not silent in the output, though, because every
   non-empty `Get Next Item` would then get the unmatched TODO. Separately, `QueueBinding` entries with
   an empty `expression_pattern` are skipped silently (L140) rather than rejected. That field also
   needs `min_length=1`.

   `WorkQueue: %QueueId%` with no TODO/VERIFY (L1629-1630). This is the same "no silent fallback"
   defect class as prior gap 2, just on the other branch. PID_0171 never reaches it (both rendered
   sites have `[ConfigFileData.Queue Name]`), but the other ~199 automations could.

## Most significant gaps

1. **Empty or missing `Queue Name` still falls back silently to `%QueueId%`** (`pad.py` L1629-1630).
   It should emit the same `# TODO: WorkQueues.<method> …` marker, for example
   `queue expression '' — no Queue Name input`. It needs a test.

   (`tests/generator/test_pad.py` L2860). It should assert the precondition instead of `if`-guarding
   it. Better still, monkeypatch `load_rules` to return a stub catalogue, construct `PADGenerator()`,
   and assert the stub's `pad_variable`/`notes` reach the rendered output.
3. **The render-path append of the unmatched TODO is untested** (`pad.py` L1966-1967). A
   `_render_stage`-level test with a stub stage whose `Queue Name` is unmatched would close it.
4. **The binding match is a substring match** (`pad.py` L1599, `expr_pattern in queue_name`), so
   `[ConfigFileData.Queue Name Backup]` would bind to `txt_WorkQueueId` silently. It should compare
   against the bracket-stripped expression exactly.
5. **`QueueBinding` accepts empty `expression_pattern`/`pad_variable`** (`config.py` L66-71). Empty
   patterns are skipped silently at `pad.py` L140. An empty `pad_variable` renders `%QueueId%` with a
   malformed VERIFY. Both fields should be `Field(min_length=1, …)`.
6. Cosmetic: the double period in the rendered VERIFY line (`pad.py` L1608 plus the trailing `.` in
