## Most significant gaps
1. **Silent content drop on the per-page (legacy) path.** The implementer raised this as an open question. `customizations_workflows.xml.j2` drops `<Definition>` for all Category 5 entries, so an all-CLOUD page packaged through the non-consolidated path loses its `.robin` text entirely. I confirmed this empirically, and no test covers it. It is not reachable from `flowsmith convert` for any process with a Main page, which makes it low severity. It still breaks the "never silently drop" rule on a reachable `SolutionPackager` path. **Suggested fix (a coordinator decision, one line of scope):** either raise `GenerationError` when the per-page path produces a Category 5 workflow, or restrict the template's omission to consolidated CF entries (e.g. an explicit `workflow.is_logic_app` flag). Retiring the per-page path would also resolve it.
2. **The collision TODO covers `SET` only (declared deviation 3).** Action outputs (`… => txt_<ConfigVar>`, `Out_*=> txt_<ConfigVar>`) that overwrite a config variable are not flagged. There are 0 such writes on PID_0171, but they are a latent risk for the ~199 other automations.
3. **The Main-body `skip_until_config_call=True` wiring is unguarded (mutation I survives).** Flipping it to `False` passes all tests. A small integration test would close this: a Main body with an init `SET` of a config variable before `CALL 'Load Config Data'` must not be flagged, and one after it must be.
4. **The `flg_Screenshot`/`flg_ConfigError` flags are never initialised, and `Get Error` is a stub.** This is disclosed with a citing `# TODO` and is owned by other tasks. It is not a 7d defect.
5. **Carry-over, already accepted:**

   - The Load Config body is not indented (cosmetic).
