## Most significant gaps

1. **Regression: Loader `dtb_MailItems` wiped after the CALL that returns it** (L113 → L127). This is
   item 8's own named example. The cause is twofold:
   - `Populate Queue`'s `Mail Items` is its Start input, and nothing excludes it from the copy's inits;
   - Main Page's `Mail Items` DATA stage is outside the Loader's role-filtered hoist set, so the
     shared-name check misses it.

   Fix within the rules: compute the "declared by both host and inlined page" set from the **host
   page's** full DATA/COLLECTION declarations, not from the current body's rendered subset. Then emit
   that shared name once at the host body's top, using the inlined page's own DATA stage when the host's
   stage belongs to the other role; this is what fp3 did for this name. Separately, consider excluding an
   inlined page's own Start-input-bound items from its per-copy inits, because BP applies the caller's
   input over the initial value. That second change would need a coordinator nod, because it is not
   literally in item 8.
2. **A host-page-shared name is re-initialised in split sub-FUNCTION copies.** `num_RetryLimit` and
   `num_RetryCount` at P856-857, P1044-1045 and P1084-1085 reset Result Entry's own retry counter inside
   its retry loop (report L1958-1973). The cause is the same as gap 1: the check uses the slice's hoisted
   set, not the page's declarations. The literal rule ("declared by both the host page and the inlined
   page … not repeated in the inlined copy") requires suppression here. The implementer's commit message
   cites this very case as a *success* of per-copy init. The coordinator should confirm that the literal
   shared-name clause wins. It does lose the fold's own per-run reset, and that is an inherent PAD name
   collision; renaming is report-only.
3. **Item 11 is not met for inline_block copy placement.** Mutant M4 (inline_block branch, `pad.py`
   ~L822) survives the full suite. Tests to add:
   - an inline_block per-copy test;
   - a test where the host's shared declaration is outside the rendered role subset or split slice;
   - a test where the inlined page has a Start input captured by a preceding CALL.

   Each should be mutation-checked against gaps 1 and 2.
4. **Item-9 detector precision** (`_stage_references_data_item`, `pad.py` ~L1366-1392):
   - it scans the `_vbo_object`/`_vbo_action` metadata values, which produces the P960 false positive;
   - it uses a raw substring match (`sampleid` ⊂ `old_sampleid`);
   - it ignores assignment targets (`params_map` keys such as `FinalProduct_Collection.Column8`).

   Fix: match bracketed/dotted data-item tokens (`[name]`, `[name.`, `name.` at a key start), skip `_`-prefixed metadata keys, and include keys.
