## Most significant gaps
1. **The amendment's required item-1 regression test is missing, and item 2 has no test either.** I reverted both fixes in a scratch copy and 326/326 generator/e2e/cli tests still passed. Tests are needed for: (a) the packager raising `GenerationError` on `cf_files` in the consolidated path; (b) a Category-5 `<Workflow>` having no `<Definition>`; (c) the CF `<JsonFileName>` file containing `properties.definition`, not a hollow stub. Adding them needs only in-scope test files.
2. **Load Config Data omits the reference's §A5 `BLOCK 'Assign values from config' ON BLOCK ERROR` wrapper (Loader L214-220), and emits no TODO saying so.** This needs a decision: add the wrapper via `actions/error_block.robin.j2`, or keep the omission and emit a TODO.
3. **§B12 environment-exposed DATA items (9 with no initial value on PID_0171) are not named.** A single generic TODO prints unconditionally, and `txt_GenericSupportTeamEmailID` is read (Performer L316) without ever being assigned. Fixing this is blocked on a parser/AST task to capture `<exposure>`. Until then, the generic TODO should at least not print for processes that have no such items.
4. **`CONFIG_PARSE_LINE` is an inline PAD action line in Python** (`pad.py:95`), contrary to CLAUDE.md's templates rule. The implementer disclosed it. This needs a scope decision to allow a new `templates/pad/actions/` template.
5. **Config-vs-page-data-item name collisions (17 names) are silent.** They are harmless on PID_0171: one write (`txt_MailSubject`, never read back in the Performer) and one read (`txt_ProductException`, which receives the same value). They are a latent hazard for other automations. This needs a policy decision: flag the collision with a TODO, or use a distinct prefix or namespace.
6. **Minor issues:**
   - `packager.py` silently falls back when the CF JSON doesn't decode, and there is a stale comment at L143-146.
   - Text config values feed `In_num_*` parameters with no VERIFY.
   - `TODO_UntranslatedCondition` is an uncited placeholder token. It fires 0 times on PID_0171, and I consider it acceptable pending sign-off.
   - Redundant local `import re` in `_extract_config_references`.
   - `_extract_config_references` doesn't scan `exception_detail`, `code_text` or the input/output maps. It is complete for PID_0171 (37 = 37) but not guaranteed to be complete for other processes.
