## Spot-check findings (coordinator's items)

1. **The third `Get Next Item` (`Queue Name=[Queue Name]`, report L1151)** is on page
   `Mark leftout Items as Exception` (confirmed from `ast.json`). That page is
   `shape: "stop"` in `mapping/page_target_map.yaml` L172-174, citing architecture §B14 row 21.
   The architecture doc (L702-708) records it as a documented STOP open question, so it is
   **correctly not rendered**, and its absence doesn't matter for 7a's *Done when*. However, it is
   exactly the input that would hit the silent fallback path described in the VBO row: if that
   page is ever un-STOPped, it would render `WorkQueue: Queue Name` with no marker. Separately (not
   7a): no `leftout` string appears anywhere in the generated `.robin` files, so the STOP page
   leaves no trace comment in the output. That belongs to Task 4a/5a.
2. **`pad.py` L132-155** — confirmed. `except Exception: pass` breaks CLAUDE.md's rule "NEVER return
   None to signal failure. ALWAYS raise a typed exception". A malformed `queue_bindings` entry
   (e.g. a string rather than a mapping → `AttributeError`) would be swallowed. The generator would
   then quietly go back to emitting `WorkQueue: ConfigFileData.Queue Name` (reproduced by clearing
   `queue_bindings`), which is the exact defect the 09-04 review rejected, and nothing would say so.
   The `Path.cwd()` resolution matches `load_rules()` (`config.py` L24 `_MAPPING_DIR =
   Path("mapping")`, also cwd-relative), so there is **no** path-divergence bug. The real problem
   is that the file is read twice, and `queue_bindings` bypasses the Pydantic `VBOEntry` model
   entirely: `VBOEntry` has no such field and silently ignores it, so nothing validates its shape.
   The implementer's commit says this was to avoid touching `config.py`, which is outside 7a's
   declared file scope. That constraint is legitimate, but it should have been reported as a
   scope-widening need rather than worked around with a silent `except`.
3. **VERIFY text** — confirmed. `pad.py` L1956-1961 hardcodes `obj_Config['Ctrl_WorkQueueId']`
   and `DF_PID_171_US_LIMS_Prelude_Main.robin.txt L150`. It pulls the variable out with
   `substituted.split('WorkQueue: ')[1].split()[0]`, which is fragile and would raise
   `IndexError` if a template ever omitted the `WorkQueue: ` token. It is also gated on
   `method_name == "Get Next Item"`. The catalogue-derived `dependency_comment`
   (L1611) is computed and then discarded. So for any other automation's binding, the marker would
   still state PID_171's `Ctrl_WorkQueueId` and L150.
4. **Tests:**
   - **Unmatched-expression test: missing.** No test covers a `Queue Name` with no catalogue
     binding.
   - **Stub-catalogue test (binding comes from the catalogue, not Python): missing.**
     `test_queue_bindings_are_in_catalogue_yaml` (test_pad.py L2711-2756) only checks the YAML file
     contents. It never checks that the generator *consumes* them. Reverting `pad.py` to the old
     hardcoded `if "ConfigFileData.Queue Name" in queue_name` would still pass every test.
   - **The strengthened assertions are content-wide, not per-site.** `"WorkQueue: txt_WorkQueueId"
     in content` and `verify_marker in content` (L2642-2650) pass as long as at least one site is
     correct. They don't check that the marker comes right before the call, and they don't check
     that *every* `ProcessWorkQueueItem` binds to `txt_WorkQueueId`.
   - **Stale comments: fixed.** No `dtb_ConfigFileData` remains in test_pad.py, and L2627-2631 now
     describe the catalogue binding.

## Most significant gaps

1. **A silent `except Exception: pass` around `queue_bindings` loading** (`pad.py` L153-155). This
   is a CLAUDE.md violation added by this pass. On failure it silently brings back the rejected
   `ConfigFileData.Queue Name` output. It should raise `GenerationError` (from `exceptions.py`),
   the same way the adjacent `load_rules()` block does at L127-130. Fixing it properly means adding
   `queue_bindings` to `VBOEntry` in `mapper/config.py`, which is outside 7a's scope and needs the
   coordinator to approve widening the scope.
2. **The unmatched-queue-expression path is still silent** (`pad.py` L1615-1620). It emits
   `WorkQueue: Queue Name` / `%QueueId%` with no TODO/VERIFY. The brief required that unmatched
   expressions not fall back silently. The fallback should emit `# TODO: WorkQueues.Get Next Item
   queue expression '<raw>' has no catalogue queue_binding` (or similar).
3. **The VERIFY marker content is hardcoded in Python, not taken from the catalogue** (`pad.py`
   L1956-1961). It should render from the binding's `citation`/`notes`, and the unused
   `dependency_comment` should either be used for this or removed. The string-split extraction of
   the variable should be replaced by the `pad_variable` already in hand.
4. **The tests requested for (c) are incomplete.** There is no unmatched-expression test, and no
   stub-catalogue test proving the generator reads the binding from YAML. The new assertions are
   content-wide rather than per-call-site with adjacency.
5. **Carried forward, still open, out of this pass's scope:**
   - `Tag Item`/`Defer` fallback `SET Tag_Item`/`SET Release_Item` lines (→ 7d)
   - `Update Status` double-quoted literals (→ 5b)
   - 7b hand-off line for the Mark Exception variants (coordinator)
   - the `SET txt_WorkQueueId` assignment itself (needs an owner, presumably 7d item 3)
   - the `Mark leftout Items as Exception` STOP page leaves no trace in the output (4a/5a)

## Verdict

**Needs another implementation pass.** It is small, and it touches only `pad.py` plus
`test_pad.py`, apart from one scope decision. The *Done when* is met, and the output is
materially more honest than at `dd8fc02`:
- the dangling binding is now flagged

But this pass added a silent-failure `except` that CLAUDE.md forbids. It left the brief's
"no silent fallback for unmatched expressions" requirement unmet. It also didn't add the two
tests that would stop a regression to hardcoded Python.

- replace the bare `except` with a typed `GenerationError`

- render the VERIFY text from the catalogue binding
- add the unmatched-path test and the stub-catalogue/consumption test
